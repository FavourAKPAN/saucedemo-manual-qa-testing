# Test Plan

## 1. Project Information

**Project:** SauceDemo Manual QA Testing  
**Testing Type:** Manual Functional Testing  
**Application:** SauceDemo  
**Environment:** Chrome on Android 14

## 2. Objective

The objective is to validate key e-commerce workflows, verify expected behaviour with valid and invalid inputs, and identify functional or validation issues.

## 3. Scope

### In Scope
- User login
- Product details and navigation
- Add to cart
- Cart quantity management
- Cart totals
- Checkout validation
- Payment processing
- Order confirmation
- Continue Shopping

### Out of Scope
- Performance testing
- Security testing
- API testing
- Database testing
- Cross-browser testing
- Automated testing
- Accessibility compliance testing
- Load/stress testing

## 4. Testing Approach

Testing was performed manually using predefined scenarios and test cases. Positive, negative, boundary/input validation, and requirement-based testing were used.

## 5. Test Environment

| Item | Details |
|---|---|
| Device | Android |
| OS | Android 14 |
| Browser | Google Chrome |
| Method | Manual |
| Application | E-commerce web application |

## 6. Test Data

- Valid and invalid login credentials
- Empty fields
- Invalid email/username formats
- Long password input
- Available products
- Different cart quantities
- Valid checkout information
- Application-provided valid test payment details

## 7. Entry Criteria

- Application is accessible.
- Login page is available.
- Required test credentials are available.
- Target workflows are accessible.

## 8. Exit Criteria

- Planned test cases have been executed.
- Actual results are documented.
- Failed tests have been reviewed.
- Confirmed defects have been documented.
- Test summary has been prepared.

## 9. Defect Classification

### Severity
- **High:** Major functionality is significantly affected.
- **Medium:** Important functionality is affected but a workaround may exist.
- **Low:** Minor functionality or usability issue is affected.

### Priority
- **High:** Requires urgent attention.
- **Medium:** Should be addressed as part of normal development priorities.
- **Low:** Can be addressed later.

## 10. Deliverables

- Test Plan
- Test Scenarios
- Test Cases
- Test Execution Report
- Test Summary Report
- Bug Reports
- Screenshots/Evidence

## 11. Limitations

Testing was limited to manual functional testing on one device/browser combination. Results therefore do not represent behaviour across all devices, browsers, network conditions, or configurations.
